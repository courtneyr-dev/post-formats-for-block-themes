# Documentation plan

Planning record for the user documentation set: scope, decisions, open questions, and items needing maintainer review.

## Plugin summary

Post Formats for Block Themes (version 2.4.0, plugin header) modernizes WordPress post formats for block themes: 9 registered formats plus standard (10 editor choices), a format selection modal, a Format Switcher sidebar panel, apply-once automatic format detection, format-specific patterns with locked first blocks, a Chat Log block (Slack/Discord/Teams/Telegram/WhatsApp/Signal), Format Badge/Icon/Post Format blocks, a Repair Tool, an icon set setting, and opt-in block templates. Requires WordPress 6.9+, PHP 7.4+, and a block theme (self-deactivates otherwise). Listed on WordPress.org.

## Audience

Site owners, admins, and editors on block themes: bloggers and content creators publishing mixed content types, classic-theme migrators, and admins maintaining format hygiene. Not primarily developers, though a "For developers" pointer section links the existing developer docs.

## Key user tasks

1. Install and activate on a block theme; confirm the modal appears.
2. Choose a format on a new post; change it via the Format Switcher.
3. Publish a chat transcript with the Chat Log block.
4. Post a status update within the 280-character counter.
5. Show formats on the site (Format Badge/Icon/Post Format blocks).
6. Change the icon set at Settings → Post Formats.
7. Fix mismatches at Tools → Post Format Repair.
8. Optionally enable plugin block templates at Tools → Post Format Templates.
9. Customize format templates/styles in the Site Editor (linked guides).

## Assumptions

- The WordPress.org listing is live (Plugin URI, stable tag 2.4.0, readme.txt install instructions, and an SVN deploy workflow all point to it), so docs include the Plugins → Add New install route.
- The compiled `build/` output present in the repository is current, so GitHub clone installs need no build step.
- The `img/` screenshots (identical files to `.wordpress-org/screenshot-2..6.png`) accurately represent current UI; they carry descriptive filenames that were verified visually against their content.
- HANDOFF-MERGE-THEME-JSON-FIX.md describes a historical bug (deep-merge fix is on main), so it's excluded from user docs.
